## 2. Модель НПЗ

Цикл: **качалка → трубы → хранилище → трубы → НПЗ → сразу бензин, дизель, мазут во внутренних складах НПЗ →
отгрузка с НПЗ по ценам продуктов.**

- **Одна клетка, клиент сети.** НПЗ — клиент существующей трубопроводной сети, как терминал. Пропускная способность, обходы, узкие места, кнопки подключения работают без новых правил. Отдельной транспортной системы нет.
- **Без бака сырья.** Забранная за шаг нефть сразу перерабатывается. Сырьё существует только в хранилищах сети — двойного учёта нет.
- **Три склада продуктов внутри НПЗ.** У каждого продукта своя ёмкость. По трубам продукты не ходят.
- **Фильтр сырья** `feed: 'any' | 'light' | 'heavy'` и флажок **«только при положительной марже»** входят в первую версию ядра.
- **Главное правило:**
  - сорт, маржа и место на складах проверяются **до** забора нефти;
  - НПЗ не забирает сырьё, которое не сможет переработать в этот же шаг.

### 2.1. Сколько НПЗ просит за шаг (предварительная проверка)

Для НПЗ на шаге `dt`:

1. **Допустимые сорта.**
   - Это пересечение фильтра и, при включённом флажке, сортов с положительной маржой: `margin(g) > 0`, см. раздел 3.
   - Если допустимых сортов нет — нефть не забирается; статус «ждёт выгодную цену» или «нет подходящего сырья».
2. **Предел по складам.** Он должен гарантировать, что продукты поместятся при любой смеси допустимых сортов:
   ```
   need = min( capacity·dt,  min по допустимым g, по продуктам i с y_i(g) > 0 :  free_i / y_i(g) )
   ```
   где `free_i = cap_i − stock_i`.
   - Если `need ≤ ε` — нефть не забирается, статус «склад <продукта> заполнен».
3. **Распределение.** НПЗ участвует в распределении с этим `need` и может забрать нефть только из хранилищ допустимых сортов (маска сортов клиента).

Так нефть никогда не уходит из резервуара, если продукт некуда положить. Переработка без остатка — следствие пункта 2.

### 2.2. Переработка забранного

Для каждой поставки `a` барр. сорта `g` из распределения:
```
gas = a · y_gas(g)
dsl = a · y_dsl(g)
maz = a − gas − dsl          ← остаток, а не умножение: сумма продуктов в точности равна a
```
- Потерь в MVP нет: [предл.] `REFINERY.loss = 0`.
- Параметр потерь можно добавить позже как отдельный учитываемый поток `totals.refineryLoss`.

## 3. Экономика

### 3.1. Формулы

- `P` — цена лёгкой нефти [код]; `s` — скидка тяжёлой [код].
- Цена сорта: `crude(g) = P` для лёгкой, `P·(1 − s)` для тяжёлой [код, `gradePrice`].
- Цена продукта i [предл.]:
  ```
  P_i = B_i · (1 + α·(P/50 − 1)) · c_i(t)
  ```
  - `B_i` — база при P = $50;
  - `α` — насколько продукты следуют за нефтью;
  - `c_i(t)` — собственный цикл продукта: функция времени и seed, как `heavySpread`, без нового состояния и без сдвига ГСЧ.
- Стоимость корзины из барреля сорта g: `V(g) = Σ y_i(g) · P_i`.
- Маржа на баррель (основа флажка): `margin(g) = V(g) − crude(g)`.
  - Это **предельная** выгода: продать баррель сырьём через терминал или переработать его.
  - Содержание НПЗ во флажок **не входит**. Это постоянный расход: он платится и при простое, поэтому для уже построенного НПЗ верное решение «перерабатывать, если margin > 0».

**Сравнение стратегий при одинаковом потоке сырья F барр./с:**
- выручка прямой продажи: `R_dir = F · crude(g)` (через терминал);
- выручка переработки: `R_ref = F · V(g)`;
- **валовой прирост выручки:** `ΔR = R_ref − R_dir`;
- **чистый дополнительный результат:** `ΔN = ΔR − U`, где `U` — содержание НПЗ.

Если флажок остановил НПЗ, то `ΔN = −U`: сырьё продаётся напрямую, содержание платится.

- Окупаемость: `T = стоимость НПЗ / ΔN` (только при ΔN > 0).

Допущения сравнения:
1. Поток сырья один и тот же: F = 2 барр./с — производительность НПЗ 1-го уровня.
2. Терминальная мощность для прямой продажи уже есть (терминал нужен и для остальной нефти). Его содержание общее для обеих стратегий и в ΔN не входит.
3. Продукты продаются сразу (пороги 0), склады не переполняются.
4. Цены постоянны на интервале расчёта.

### 3.4. Сценарий E: продукт некуда складывать

Условия: B1 (лёгкая, всё благоприятно), но игрок держит мазут — порог $40 при цене $37,50.
- Поток мазута: 2 · 0,20 = 0,4 барр./с. Склад 200 барр. заполнится за **500 с ≈ 8,3 мин**. На тяжёлой: 2 · 0,45 = 0,9 барр./с, заполнится за **222 с ≈ 3,7 мин**.
- Дальше НПЗ **не забирает нефть** (предварительная проверка 2.1). Нефть остаётся в резервуарах и уходит терминалам, а при заполнении сети качалки встают по уже существующему правилу.
- Цена удержания:
  - ожидание +$2,50 на баррель даёт 200 · 2,5 = **$500** за весь склад;
  - простой лишает валового прироста ΔR = **$21,25/с**;
  - удержание окупается, только если цена вырастет раньше, чем через 500 / 21,25 ≈ **24 с** простоя.
- Что делать игроку: снизить порог мазута, переключить сырьё на лёгкую (мазута меньше), улучшить НПЗ (склад больше).

## 4. Конкуренция НПЗ и терминалов за сырьё

**Правило [предл.]: НПЗ и терминалы — клиенты одного и того же шага распределения.**

Сейчас терминалы забирают нефть отдельным шагом до качалок. НПЗ добавляется **в тот же вызов `allocate`**, что и терминалы. В каждом раунде:

1. Каждый клиент (терминал или НПЗ) выбирает ближайшее по длине трубы хранилище, где есть нефть **допустимого для него сорта**:
   - для терминала — сорта, цена которого не ниже порога продажи [код];
   - для НПЗ — фильтр ∩ положительная маржа (2.1).
2. Если на одно хранилище претендуют несколько клиентов, оно делится **пропорционально запросам**. Это существующая формула `asked`/`room` [код], без приоритета по типу.
3. Трубы общие, ограничение тоже пропорционально — существующая формула нагрузки [код].
4. Недобор переходит в следующий раунд к следующему хранилищу.

Так ни один тип здания не получает скрытого преимущества от порядка. Решения принимаются по состоянию, применяются одновременно, ничьи решает номер клетки [код].

Если игроку нужна переработка вместо продажи, он управляет этим явно:
- порогом цены терминала (поднять — терминал не заберёт сырьё);
- выключением терминала;
- фильтром сорта НПЗ;
- раскладкой сети (НПЗ ближе к нужным резервуарам).

**Тесты:**
1. Перемешанный массив зданий (НПЗ, терминалы, качалки) даёт тот же результат: запасы, продукты, выручка, статусы.
2. Одно хранилище с 1,5 барр., терминал просит 1, НПЗ просит 2 (на шаг): получают 0,5 и 1,0 — пропорционально запросам; при равных запросах — поровну.
3. Перестановка id НПЗ и терминала, равноудалённых от хранилища, результат не меняет.

## 5. Продажа нефтепродуктов

- **Где.** С самого НПЗ, его собственной отгрузкой (автоцистерны). Через трубы и терминалы продукты не идут.
- **Мощность отгрузки.** `ship·dt` барр. за шаг, суммарно по продуктам [предл.]: 4 / 9 / 18 барр./с.
  - Если продаваемых продуктов больше, чем мощность, она делится пропорционально запасам продаваемых продуктов.
  - Мощность вдвое выше переработки, поэтому при порогах 0 склады не копятся. После удержания запас уходит со скоростью до (отгрузка − поступление).
- **Пороги цены.**
  - Один порог на каждый продукт для всех НПЗ компании (как сейчас общий порог терминалов) [предл.].
  - Продукт продаётся, только если его цена не ниже порога; по умолчанию порог 0.
- **Полный склад.**
  - Склад заполнен, если `free_i ≤ ε` для любого продукта с ненулевым выходом у допустимых сортов.
  - Тогда переработка останавливается целиком, нефть не забирается (2.1), а продажа других продуктов продолжается.
  - Освободилось место — переработка возобновляется сама.
- **Осознанное упрощение MVP: спрос неограничен.** Рынок продуктов принимает любой объём по текущей цене, без влияния объёма на цену. Сейчас так же устроена продажа нефти [код]. Ограничение спроса — отдельная задача на будущее.
- **Перекупщика для продуктов в MVP нет.** Исключение — снос НПЗ (раздел 6).

- **`actions.ts`**:
  - правило постройки как у терминала (не на месторождении);
  - настройки `feed`, `marginOnly`, порогов;
  - снос — остаток продуктов продаётся перекупщику (80% цены продукта) и учитывается как продажа, без потерь.
- **`connect.ts:175`**: варианты подключения для НПЗ; желаемый поток — переработка уровня.
- **`objectives.ts`**: цель «Переработка» после «Прибыль $6 000/мин»; та цель открывает НПЗ.
- **Рендер**: только новая модель НПЗ из примитивов `ModelPainter` (`models.ts`, `sprites.ts`, `renderer.ts:883`). Существующие модели не меняются.
- **Интерфейс**: `hud.ts:7` (список зданий), панель НПЗ, статусы, `main.ts` (клавиша 6).

## 7. Интерфейс

- **Строительство:** карточка «НПЗ» (клавиша 6) с ценой, переработкой и содержанием, как у остальных зданий.
- **Панель НПЗ:**
  - статус и причина: не подключено; нет подходящего сырья; склад <продукта> заполнен; переработка сейчас невыгодна; ограничено трубой;
  - загрузка: фактически / максимум, барр./мин, и сорт текущего сырья;
  - продукты: запас / ёмкость, цена с трендом, ползунок порога;
  - сырьё: переключатель «любая / лёгкая / тяжёлая», флажок «только при выгоде»;
  - сравнение по каждому сорту: «1 барр.: продать $50,00 / переработать $60,63 (+$10,63)»;
  - итог при полной загрузке: «+$X/мин с учётом содержания» — это ΔN из 3.1.
- **Финансы:** строка «Выручка от нефтепродуктов».
- **Значки:** «!» — склад продукта полон; «$» — ждёт выгодную цену.

## 8. Бот

Строит НПЗ только если **все** условия выполнены:
1. НПЗ открыт, денег не меньше 1,5 его цены.
2. **Доступный поток сырья.**
   - Фактическая добыча за последнюю минуту минус фактическая отгрузка терминалов не меньше 75% переработки уровня 1.
   - Либо добыча за минуту не меньше суммы мощности терминалов и переработки.
3. **Подключение.**
   - Выбранная клетка рядом с хранилищем, а прогноз потока НПЗ (`connectOptions`, пробный расчёт) не меньше 75% мощности.
   - Иначе — не строить.
4. **Сырьё.** Хотя бы у одного сорта, который есть в достижимых хранилищах, маржа по базовым ценам (c = 1, текущая P) положительна.
5. **Сбыт.** Пороги продуктов бота — 0, отгрузка вдвое выше переработки, поэтому продукты не копятся.

В работе:
- флажок «только при выгоде» всегда включён;
- если склад продукта полон — порог этого продукта в 0;
- улучшать НПЗ, если загрузка выше 90% последние 2 минуты, а маржа доступного сорта положительна.

Решения игрока, которые бот не принимает:
- удерживать продукты ради цены;
- выбор сорта сырья;
- долгая консервация НПЗ;
- распределение резервуаров между продажей и переработкой.

## 9. Сохранения, инварианты, тесты

**Сохранения v4 → v5:**
- `productThresholds = [0, 0, 0]`, новые поля в `totals` равны 0;
- номер цели сдвигается, если новая цель вставлена раньше текущей;
- если «Прибыль $6 000» уже пройдена, `'refinery'` добавляется в открытые здания;
- остальное без изменений.

**Инварианты (тесты на каждом шаге в сценариях):**
1. Нефть: `produced − sold − refined = Σ stored`.
2. Продукты, для каждого i: `productsMade_i − productsSold_i = Σ stock_i ≥ 0`, и `Σ_i productsMade_i = refined`.
3. Деньги: `cash = старт + выручка + награды + компенсации − расходы − вложения`. Выручка включает продукты.
4. Склад продукта никогда не превышает ёмкость; нефть не уходит из резервуара, если её нельзя переработать.
5. Результат не зависит от порядка зданий (раздел 4).

**Остальные тесты:**
- выход продуктов по сортам;
- предварительная проверка: полный склад → нефть не забирается;
- фильтр сорта;
- флажок маржи на сценариях C3 и D2;
- конкуренция с терминалами (4.2, 4.3);
- узкое место трубы к НПЗ;
- пороги и отгрузка продуктов;
- снос с остатком;
- шаг 0,1 против 1 с (офлайн);
- миграция v1 → v5;
- баланс на трёх картах с прежними границами.

**Производительность:** НПЗ — ещё несколько клиентов в существующем распределении. Проверка — время прогона бота и `renderer.frameMs`.

## 10. Решения, требующие отдельного согласования

1. **Параметры экономики:** выходы, базы цен, α = 0,5, циклы, уровни (цены, содержание, переработка, склады, отгрузка).
2. **Смысл флажка маржи:** предельная маржа на баррель **без** учёта содержания (см. 3.3, C1). Альтернатива — с учётом содержания, но тогда НПЗ стоял бы и в ситуациях, где работать выгоднее.
3. **Общая очередь НПЗ и терминалов** с пропорциональным разделом (раздел 4), без приоритета и без отдельной настройки.
4. **Пороги продуктов** — общие для компании, а не на каждый НПЗ.
5. **Снос НПЗ:** остаток продуктов продаётся перекупщику по 80% (а не запрет сноса).
6. **Потери** при переработке — 0 в MVP.
7. **Цель и открытие:** новая цель «Переработка» после «Прибыль $6 000/мин»; та цель открывает НПЗ. Награда за новую цель — предлагаю $5 000.
8. **Неограниченный спрос** на продукты в MVP.
9. **Одна клетка и новая модель НПЗ** (существующие модели не меняются). Клавиша 6.
