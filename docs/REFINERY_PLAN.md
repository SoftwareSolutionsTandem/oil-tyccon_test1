## 2. Модель НПЗ

Цикл: **качалка → трубы → хранилище → трубы → НПЗ → сразу бензин, дизель, мазут во внутренних складах НПЗ →
отгрузка с НПЗ по ценам продуктов.**

- **Одна клетка, клиент сети.** НПЗ — клиент существующей трубопроводной сети, как терминал. Пропускная способность, обходы, узкие места, кнопки подключения работают без новых правил. Отдельной транспортной системы нет.
- **Без бака сырья.** Забранная за шаг нефть сразу перерабатывается. Сырьё существует только в хранилищах сети — двойного учёта нет.
- **Три склада продуктов внутри НПЗ.** У каждого продукта своя ёмкость. По трубам продукты не ходят.
- **Фильтр сырья** `feed: 'any' | 'light' | 'heavy'` и флажок **«только при положительной марже»** входят в первую версию ядра.
- **Главное правило:**
  - сорт, маржа и место на складах проверяются **до** забора нефти;
  - НПЗ не забирает сырьё, которое не сможет переработать в этот же шаг.

### 2.1. Сколько НПЗ просит за шаг (предварительная проверка)

Шаг `tick()` [код, `sim.ts:17`, `:20`] сначала обновляет рынок, затем логистику. Поэтому цена нефти, скидка, цены продуктов и маржа внутри одного шага **постоянны**.

Порядок для каждого НПЗ на шаге `dt`:

0. **Продажа продуктов** (раздел 5) — до забора нефти, чтобы проданное в этом шаге освободило место. Продукты, полученные в этом шаге, продаются со следующего шага.
1. **Допустимые сорта** — маска `M`, фиксируется до распределения и не меняется в шаге:
   ```
   A = сорта, разрешённые фильтром feed          (any → {0,1}, light → {0}, heavy → {1})
   M = A ∩ { g : margin(g) > 0 }                 если marginOnly
   M = A                                         иначе
   ```
2. **Свободное место** с запасом на погрешность:
   ```
   free_i = max(0, cap_i − stock_i − ε_cap)      ε_cap = 1e-9 барр.
   ```
3. **Худший выход по каждому продукту** среди допустимых сортов:
   ```
   ŷ_i = max_{g ∈ M} y_i(g)
   ```
4. **Допустимый объём**:
   ```
   need = min( capacity·dt ,  min_{i : ŷ_i > 0}  free_i / ŷ_i )
   ```
   - Если `M` пусто или `need ≤ ε` (ε = 1e-9 барр.), нефть не забирается вовсе. Статус — по правилу 2.3.
   - Это та же формула, что `min_{g∈M, i} free_i / y_i(g)` из первой версии, записанная через худший выход. Значения совпадают, но так видно, почему она верна для смеси.
5. **Распределение.** НПЗ участвует в общем распределении (раздел 4) с запросом `need`. Нефть он получает только из хранилищ, сорт которых входит в `M`: маска сортов клиента проверяется при выборе хранилища.

**Утверждение.** При любой смеси сортов, полученной в шаге, `stock_i` после переработки не превышает `cap_i` ни для какого продукта.

**Доказательство.**
- Пусть за шаг НПЗ получил `a_g ≥ 0` барр. сорта g; получать можно только сорта из `M`.
- Распределение не выдаёт клиенту больше запроса. Каждый раунд начинается с остатка `need`, умножает его только на множители ≤ 1 (узкое место трубы, доля хранилища) и вычитает выданное [код, `network.ts`, `allocate`]. Значит `Σ_g a_g ≤ need`.
- Для продукта i:
  ```
  made_i = Σ_g a_g · y_i(g) ≤ Σ_g a_g · ŷ_i ≤ need · ŷ_i ≤ free_i
  ```
- Итак `stock_i + made_i ≤ cap_i − ε_cap`. Для продукта с `ŷ_i = 0` выход равен 0.

Формула **консервативна**: для конкретной смеси может поместиться больше, но смесь до распределения неизвестна. Отказ в лишнем объёме безопасен — нефть просто остаётся в резервуаре.

Необходимые предположения (каждое проверяется тестом):
1. Выходы неотрицательны, и для каждого сорта `Σ_i y_i(g) = 1` (тест конфигурации).
2. `M` и цены не меняются в шаге: маска считается один раз до распределения.
3. Поставки НПЗ — только из хранилищ сортов `M`: маска применяется при выборе хранилища в каждом раунде.
4. Суммарная поставка за шаг ≤ `need` (свойство `allocate`, тест).
5. Продажа продуктов идёт до расчёта `free_i` и только уменьшает `stock_i`.

**Дробные объёмы и погрешность.** Объёмы — вещественные числа, округление только в отображении.
- Мазут считается как остаток (2.2). В плавающей точке он может превысить точное `a·y_maz` на несколько ULP, то есть на величину порядка `1e-16·a`.
- Запас `ε_cap = 1e-9` на много порядков больше этой ошибки, поэтому склад не переполняется и после округления.
- Обрезать продукт до ёмкости не нужно и **запрещено**: это была бы потеря ресурса.
- Тест проверяет `stock_i ≤ cap_i` после каждого шага.

### 2.3. Статус НПЗ и порядок причин

Для пояснений: `S` — сорта, которые сейчас есть (`stored > ε`) в хранилищах, достижимых НПЗ по сети. Достижимость считается без учёта насыщения труб. `A` и `M` — из 2.1.

Причины проверяются **по порядку**. Статус — первая выполненная причина. Остальные выполненные причины панель показывает дополнительными строками («Также: склад мазута заполнен»).

| # | Условие | Статус | Текст |
|---|---|---|---|
| 1 | НПЗ выключен игроком | `off` [код] | «Законсервировано» |
| 2 | Нет пути до хранилища | `no_route` [код] | «Не подключено к хранилищу» |
| 3 | `A ∩ S` пусто | `no_feed` | «Нет сырья подходящего сорта» (фильтр не пропускает имеющиеся сорта, или нефти нет) |
| 4 | `marginOnly` и `M ∩ S` пусто | `waiting_margin` | «Переработка сейчас невыгодна» (маржа всех доступных разрешённых сортов ≤ 0) |
| 5 | `need ≤ ε` из-за складов (2.1, п. 4) | `product_full` | «Склад <продукта> заполнен» — продукт, на котором достигается минимум |
| 6 | Получено меньше `need` из-за узкого места трубы, а в достижимых хранилищах осталась нефть сортов `M` | `throttled` [код] | «Ограничено пропускной способностью трубы» |
| 7 | Иначе | `ok` [код] | «Работает»; если нефти меньше мощности — загрузка в процентах |

Почему такой порядок: причины идут по цепочке «есть сырьё → выгодно → есть куда девать → хватает трубы».
- Без подходящего сырья маржа и склады не важны.
- При невыгодной цене нефть не берётся независимо от склада.
- Полный склад важен, только если перерабатывать есть что и есть смысл.

Пример: склад мазута полон и маржа отрицательна → статус «переработка сейчас невыгодна», строка «Также: склад мазута заполнен».

## 3. Экономика

### 3.1. Формулы

- `P` — цена лёгкой нефти [код]; `s` — скидка тяжёлой [код].
- Цена сорта: `crude(g) = P` для лёгкой, `P·(1 − s)` для тяжёлой [код, `gradePrice`].
- Цена продукта i [предл.]:
  ```
  P_i = B_i · (1 + α·(P/50 − 1)) · c_i(t)
  ```
  - `B_i` — база при P = $50;
  - `α` — насколько продукты следуют за нефтью;
  - `c_i(t)` — собственный цикл продукта: функция времени и seed, как `heavySpread`, без нового состояния и без сдвига ГСЧ.
- Стоимость корзины из барреля сорта g: `V(g) = Σ y_i(g) · P_i`.
- Маржа на баррель (основа флажка): `margin(g) = V(g) − crude(g)`.
  - Это **предельная** выгода: продать баррель сырьём через терминал или переработать его.
  - Содержание НПЗ во флажок **не входит**. Это постоянный расход: он платится и при простое, поэтому для уже построенного НПЗ верное решение «перерабатывать, если margin > 0».

**Сравнение стратегий при одинаковом потоке сырья F барр./с:**
- выручка прямой продажи: `R_dir = F · crude(g)` (через терминал);
- выручка переработки: `R_ref = F · V(g)`;
- **валовой прирост выручки:** `ΔR = R_ref − R_dir`;
- **чистый дополнительный результат:** `ΔN = ΔR − U`, где `U` — содержание НПЗ.

Если флажок остановил НПЗ, то `ΔN = −U`: сырьё продаётся напрямую, содержание платится.

- Окупаемость: `T = стоимость НПЗ / ΔN` (только при ΔN > 0).

Допущения сравнения:
1. Поток сырья один и тот же: F = 2 барр./с — производительность НПЗ 1-го уровня.
2. Терминальная мощность для прямой продажи уже есть (терминал нужен и для остальной нефти). Его содержание общее для обеих стратегий и в ΔN не входит.
3. Продукты продаются сразу (пороги 0), склады не переполняются.
4. Цены постоянны на интервале расчёта.

### 3.4. Сценарий E: продукт некуда складывать

Условия: B1 (лёгкая, всё благоприятно), но игрок держит мазут — порог $40 при цене $37,50.

  - ожидание +$2,50 на баррель даёт 200 · 2,5 = **$500** за весь склад;
  - простой лишает валового прироста ΔR = **$21,25/с**;
  - удержание окупается, только если цена вырастет раньше, чем через 500 / 21,25 ≈ **24 с** простоя.
- Что делать игроку: снизить порог мазута, переключить сырьё на лёгкую (мазута меньше), улучшить НПЗ (склад больше).

## 4. Конкуренция НПЗ и терминалов за сырьё

**Правило [предл.]: НПЗ и терминалы — клиенты одного и того же шага распределения.**

Сейчас терминалы забирают нефть отдельным шагом до качалок. НПЗ добавляется **в тот же вызов `allocate`**, что и терминалы. В каждом раунде:

1. Каждый клиент (терминал или НПЗ) выбирает ближайшее по длине трубы хранилище, где есть нефть **допустимого для него сорта**:
   - для терминала — сорта, цена которого не ниже порога продажи [код];
   - для НПЗ — фильтр ∩ положительная маржа (2.1).
2. Если на одно хранилище претендуют несколько клиентов, оно делится **пропорционально запросам**. Это существующая формула `asked`/`room` [код], без приоритета по типу.
3. Трубы общие, ограничение тоже пропорционально — существующая формула нагрузки [код].
4. Недобор переходит в следующий раунд к следующему хранилищу.

Так ни один тип здания не получает скрытого преимущества от порядка. Решения принимаются по состоянию, применяются одновременно, ничьи решает номер клетки [код].

Если игроку нужна переработка вместо продажи, он управляет этим явно:
- порогом цены терминала (поднять — терминал не заберёт сырьё);
- выключением терминала;
- фильтром сорта НПЗ;
- раскладкой сети (НПЗ ближе к нужным резервуарам).

**Тесты** (этап 3). Принцип распределения в них не упрощается:
1. **Перестановка зданий** — перемешанный массив (НПЗ, терминалы, качалки) даёт тот же результат: запасы, продукты, выручка, статусы.
2. **Перестановка идентификаторов** — переназначенные id НПЗ и терминала при той же геометрии дают тот же результат.
3. **Раздел одного хранилища** — 1,5 барр.; терминал просит 1, НПЗ просит 2 (на шаг) → 0,5 и 1,0; при равных запросах — поровну.
4. **Общая перегруженная труба** — терминал и НПЗ за одной промысловой трубой (2 барр./с) от одного хранилища. Через трубу проходит не больше 2 барр./с, доли пропорциональны запросам, суммы сходятся с инвариантами.
5. **Альтернативные пути** — к хранилищу ведут кратчайший перегруженный путь и обход. После насыщения кратчайшего пути НПЗ и терминал получают остаток по обходу в следующих раундах (существующие обходы [код]), без потерь и без превышения пропускной способности.
6. **Разные наборы хранилищ** — НПЗ достаёт до хранилищ X и Y, терминал — до Y и Z. Общее хранилище Y делится пропорционально, недобор каждого уходит к его собственному следующему хранилищу; результат не зависит от порядка.
7. **Разные наборы по сорту** — НПЗ с фильтром «тяжёлая» и терминал рядом с лёгкой и тяжёлой нефтью. НПЗ получает только тяжёлую; лёгкая достаётся терминалу целиком.
8. **Нельзя безопасно разместить продукты**:
   - (а) склад мазута почти полон, `need` меньше доступной нефти → получено ровно ≤ `need`, `stock ≤ cap`;
   - (б) `need ≤ ε` → нефть из хранилищ не уходит, весь запас достаётся терминалу;
   - (в) смесь: разрешены оба сорта, у тяжёлой выход мазута выше, распределение даёт смесь → мазут не превышает ёмкость (проверка формулы 2.1 на смеси).
9. **Шаг 0,1 против 1 с** — сопоставимые итоги, инварианты на обоих шагах.

## 5. Продажа нефтепродуктов

- **Где.** С самого НПЗ, его собственной отгрузкой (автоцистерны). Через трубы и терминалы продукты не идут.
- **Когда.** В начале шага логистики, до забора нефти (2.1, п. 0): проданное освобождает место для переработки в том же шаге.
- **Мощность отгрузки.** `ship·dt` барр. за шаг, суммарно по продуктам [предл.]: 4 / 9 / 18 барр./с.
  - Если продаваемых продуктов больше, чем мощность, она делится пропорционально запасам продаваемых продуктов.
  - Мощность вдвое выше переработки, поэтому при порогах 0 склады не копятся. После удержания запас уходит со скоростью до (отгрузка − поступление).
- **Пороги цены.**
  - Один порог на каждый продукт для всех НПЗ компании (как сейчас общий порог терминалов) [предл.].
  - Продукт продаётся, только если его цена не ниже порога; по умолчанию порог 0.
- **Полный склад.**
  - Переработка ограничивается или останавливается по формуле 2.1: `need` уменьшается с заполнением склада и при `need ≤ ε` становится нулевым.
  - Нефть при этом не забирается, а продажа остальных продуктов продолжается.
  - Освободилось место — переработка возобновляется сама.
- **Осознанное упрощение MVP: спрос неограничен.** Рынок продуктов принимает любой объём по текущей цене, без влияния объёма на цену. Сейчас так же устроена продажа нефти [код]. Ограничение спроса — отдельная задача на будущее.
- **Перекупщика для продуктов в MVP нет.** Исключение — снос НПЗ (раздел 6).

## 8. Бот

Строит НПЗ только если **все** условия выполнены:
1. НПЗ открыт, денег не меньше 1,5 его цены.
2. **Доступный поток сырья.**
   - Фактическая добыча за последнюю минуту минус фактическая отгрузка терминалов не меньше 75% переработки уровня 1.
   - Либо добыча за минуту не меньше суммы мощности терминалов и переработки.
3. **Подключение.**
   - Выбранная клетка рядом с хранилищем, а прогноз потока НПЗ (`connectOptions`, пробный расчёт) не меньше 75% мощности.
   - Иначе — не строить.
4. **Сырьё.** Хотя бы у одного сорта, который есть в достижимых хранилищах, маржа по базовым ценам (c = 1, текущая P) положительна.
5. **Сбыт.** Пороги продуктов бота — 0, отгрузка вдвое выше переработки, поэтому продукты не копятся.

В работе:
- флажок «только при выгоде» всегда включён;
- если склад продукта полон — порог этого продукта в 0;
- улучшать НПЗ, если загрузка выше 90% последние 2 минуты, а маржа доступного сорта положительна.

Решения игрока, которые бот не принимает:
- удерживать продукты ради цены;
- выбор сорта сырья;
- долгая консервация НПЗ;
- распределение резервуаров между продажей и переработкой.

## 9. Сохранения, инварианты, тесты

**Сохранения v4 → v5:**
- `productThresholds = [0, 0, 0]`, новые поля в `totals` равны 0;
- номер цели сдвигается, если новая цель вставлена раньше текущей;
- если «Прибыль $6 000» уже пройдена, `'refinery'` добавляется в открытые здания;
- остальное без изменений.

**Инварианты (тесты на каждом шаге в сценариях):**
1. Нефть: `produced − sold − refined = Σ stored`.
2. Продукты, для каждого i: `productsMade_i − productsSold_i = Σ stock_i ≥ 0`, и `Σ_i productsMade_i = refined`.
3. Деньги: `cash = старт + выручка + награды + компенсации − расходы − вложения`. Выручка включает продукты.
4. Склад продукта никогда не превышает ёмкость (`stock_i ≤ cap_i` после каждого шага, в том числе при смеси сортов). Нефть не уходит из резервуара, если её нельзя переработать (2.1).
5. Результат не зависит от порядка зданий (раздел 4).

**Остальные тесты:**
- выход продуктов по сортам;
- предварительная проверка: полный склад → нефть не забирается; смесь сортов не переполняет склад;
- порядок статусов 2.3: по тесту на каждую строку таблицы и на совпадение причин (например, склад полон и маржа ≤ 0 → «невыгодно»);
- фильтр сорта;
- флажок маржи на сценариях C3 и D2;
- конкуренция с терминалами и трубами: все пункты теста из раздела 4;
- узкое место трубы к НПЗ;
- пороги и отгрузка продуктов;
- снос с остатком;
- шаг 0,1 против 1 с (офлайн);
- миграция v1 → v5;
- баланс на трёх картах с прежними границами.

**Производительность:** НПЗ — ещё несколько клиентов в существующем распределении. Проверка — время прогона бота и `renderer.frameMs`.

## 10. Решения, требующие отдельного согласования

1. **Параметры экономики:** выходы, базы цен, α = 0,5, циклы, уровни (цены, содержание, переработка, склады, отгрузка).
2. **Смысл флажка маржи:** предельная маржа на баррель **без** учёта содержания (см. 3.3, C1). Альтернатива — с учётом содержания, но тогда НПЗ стоял бы и в ситуациях, где работать выгоднее.
3. **Общая очередь НПЗ и терминалов** с пропорциональным разделом (раздел 4), без приоритета и без отдельной настройки.
4. **Пороги продуктов** — общие для компании, а не на каждый НПЗ.
5. **Снос НПЗ:** остаток продуктов продаётся перекупщику по 80% (а не запрет сноса).
6. **Потери** при переработке — 0 в MVP.
7. **Цель и открытие:** новая цель «Переработка» после «Прибыль $6 000/мин»; та цель открывает НПЗ. Награда за новую цель — предлагаю $5 000.
8. **Неограниченный спрос** на продукты в MVP.
9. **Одна клетка и новая модель НПЗ** (существующие модели не меняются). Клавиша 6.
10. **Продажа продуктов до забора нефти** в шаге (2.1, п. 0; раздел 5). В первой редакции она шла после переработки — уточнено, чтобы проданное в шаге сразу освобождало место.
11. **Порядок причин статуса** (2.3): сырьё → маржа → склад → труба.
12. **Определения метрик баланс-прогона** (этап 6), в первую очередь окупаемость.

### 11.1. Баланс-прогон этапа 6 (критерии будущей проверки)

Результаты не задаются заранее: здесь описаны условия и метрики, а цифры появятся только после реализации.

**Условия.**
- Бот (`tests/bot.ts`) с правилами раздела 8, карты 1–5, прогоны по **60 и 90 минут** игрового времени.
- Обычная симуляция без упрощений:
  - циклическая цена нефти [код, `MARKET`] и циклы цен продуктов [предл.];
  - оба сорта по генерации карт [код];
  - ограничения труб и обходы [код];
  - продажа продуктов с порогами и отгрузкой (раздел 5).

**Метрики отчёта** (`BALANCE_LOG`, по каждой карте и длительности). Метрики считает тестовый обвес по данным каждого шага; в `GameState` для них ничего не добавляется, кроме полей `totals` из раздела 6.

| Метрика | Определение |
|---|---|
| Денежный результат | `cash` в конце и минимум кассы за прогон |
| Выручка от сырой нефти | терминалы и перекупщик (`totals.revenue − totals.productRevenue`) |
| Выручка от продуктов | `totals.productRevenue` |
| Переработано | `totals.refined`, барр., в том числе по сортам |
| Фактическая загрузка НПЗ | `refined / Σ (мощность уровня · время с момента постройки)`, % |
| Простой | доля времени НПЗ в статусах `waiting_margin`, `product_full`, `no_feed` / `no_route` / `throttled` (логистика), % |
| Остатки продуктов | запас каждого продукта в конце прогона |
| Время окупаемости | первый момент, когда накопленный чистый результат ≥ вложений в НПЗ (строительство и улучшения), в минутах от постройки; «не достигнута», если такого момента нет |

Накопленный чистый результат НПЗ (для окупаемости), по шагам:
```
Σ (выручка от продуктов − ценность переработанной нефти − содержание НПЗ·dt)
```
- Ценность переработанной нефти = объём каждого сорта × цена сорта в момент забора. Это упущенная прямая продажа, как ΔN в 3.1.
- Остатки продуктов не учитываются, пока не проданы.

**Приёмка этапа 6:**
- отчёт выводится по всем метрикам;

## 12. Решения, принятые при реализации

1. **ŷ_i считается по M ∩ сорта, которые есть в досягаемых хранилищах.** Раньше бралось всё M.
   - Почему: иначе НПЗ с разрешённой, но отсутствующей тяжёлой нефтью занижал заявку, когда склад мазута почти полон.
   - Почему безопасно: хранилища в фазе забора только отдают нефть, новых сортов в них за шаг не появляется. Гарантия «любая смесь помещается» сохраняется (тест «смесь сортов: заявка по худшему выходу»).
2. **`epsCap` = 1e-6, а не 1e-9.** После распределения остаток продукта меньше погрешности прижимается к ёмкости. Запаса 1e-9 не хватало на накопленную погрешность сумм с плавающей точкой. Вместимость в тестах не превышается.
3. **Цель «Переработка».**
   - Прогресс — суммарно продано 200 барр. нефтепродуктов, награда $5 000.
   - Цель стоит перед «$500 000»; НПЗ открывает «Прибыль $6 000/мин».
   - Миграция v4 → v5 сдвигает индекс цели, если игрок уже прошёл «Прибыль $6 000/мин», и открывает НПЗ.
4. **`costGrowth` НПЗ = 1,5** — как у прочих зданий с ростом цены.
5. **Бот (раздел 8)** — критерии формализованы так:
   - «есть свободный поток сырья» → добыча ≥ 1,5 мощности НПЗ 1-го уровня, плюс пробный 10-секундный прогон на копии состояния (с выключенным «только при выгоде»). Место подходит, если поток ≥ 75% мощности.
   - Маржа проверяется по базовым циклам (cycle = false) хотя бы для одного имеющегося сорта.
   - Если НПЗ ограничен трубой, бот ставит ветку из вариантов «Подключить» или «Усилить маршрут» (магистраль).
   - Терминалы бот ставит, пока мощность терминалов + НПЗ меньше добычи.
   - Пороги продуктов бот держит нулевыми.
6. **Анимации отгрузки у НПЗ нет** (бензовозы — только у терминала). Дым из трубы печи — пока НПЗ работает (ok или throttled).
7. **Статус «нет сырья» («…»)** показывается и тогда, когда нефть подходящего сорта есть в сети, но фильтр её исключает. Причины, перекрытые статусом с бо́льшим приоритетом, панель перечисляет строкой «Также».
8. **Баланс-прогоны** — результаты и выводы в [DESIGN.md](DESIGN.md#баланс). Главное узкое место — трубы к НПЗ, не маржа и не склады. Значения экономики не менялись.
