# Oil Tycoon — заметки для ассистента

- Общение с владельцем проекта — **на русском**. Код, команды и идентификаторы — на английском; комментарии в коде — на русском.
- Концепция: `docs/PROJECT.md`. Решения по дизайну: `docs/DESIGN.md`. Архитектура: `docs/ARCHITECTURE.md`. План: `docs/ROADMAP.md`. Обновляй их, когда меняются решения.

## Команды
- `npm run dev` — разработка; `npm test` — тесты; `npm run typecheck`; `npm run build`.
- `BALANCE_LOG=1 npm test` — отчёт бота о темпе прохождения целей. Запускай после любых изменений чисел в `src/core/config.ts`.

## Правила
- `src/core` — без DOM и без `Math.random()` в симуляции (только `Rng` из состояния), чтобы сохранялись детерминизм и тестируемость.
- Любое изменение `GameState` → поднять `SAVE_VERSION` и добавить миграцию в `src/core/save.ts`.
- Денежный инвариант (`tests/core.test.ts`, `expectBalanced`) не должен ломаться: каждая операция с деньгами учитывается в `totals`. С вехи 0.4: `cash = START_CASH + revenue + rewards + refunds + borrowed + adRewards − expenses − capex − research − repaid − interest` (зарплаты — внутри `expenses`; `adRewards` — награды за рекламу, с вехи 0.5).
- Платформа (`src/platform/*`: `local`, `yandex`) — только в `main.ts`; ядро о ней не знает. Награда за рекламу — только `core.claimAdReward` после `onRewarded` платформы.
- Нефть лежит в хранилищах (`Building.stored`), `s.oil` — производная сумма: меняешь запасы — вызывай `syncOil`. Инвариант запасов: `добыто − продано = сумма хранилищ` без переработки — `tests/logistics.test.ts:67`; с переработкой `добыто − продано − переработано = сумма хранилищ` — `tests/refinery.test.ts:72`.
- Логистика (`src/core/network.ts`) не должна зависеть от порядка зданий в массиве: решения — по состоянию, применение — одновременно. Забор (терминалы, НПЗ) и закачка (качалки) — клиенты одного `allocate`: трубы делятся пропорционально, без приоритета фазы.
- Менеджеры и кредит работают внутри `tick` (офлайн тоже): решения менеджеров — на границах периода, долг по кредиту — замкнутая формула от времени.
- Сорт нефти: у месторождения (`map.grade`) и у хранилища (`Building.grade`); хранилище не смешивает сорта. Цены — только через `gradePrice`.
- НПЗ (`refinery`) — клиент сети в общей очереди с терминалами: один вызов `allocate`, пропорционально, без приоритетов. Заявка — только через `refineryPlan` (место на складах продуктов проверяется до забора). Цены продуктов — только через `productPrice`, без ГСЧ. Инварианты НПЗ (нефть = добыто − продано − переработано; продукты не выше ёмкости) — в `tests/refinery.test.ts`.
- `BALANCE_LOG=1 npm test` печатает и отчёт НПЗ (`tests/refinery.balance.test.ts`, 5 карт × 60/90 мин).
- Визуальную проверку делать через Playwright (`window.oilTycoon` даёт доступ к состоянию); демо-сцена — `?demo`.
- `npm run test:mobile` — мобильный бот-тестировщик (`e2e/mobile-bot.mjs`, 390×844, только касания): проходит путь новичка и проверяет, что всё в экране и доступно пальцем. Запускай после правок интерфейса. Браузер: `npx playwright install chromium` или `CHROMIUM_PATH`.
- Графика: все объекты строятся из примитивов `ModelPainter` с общим светом `LIGHT` и `MATERIALS` — не вставлять сторонние картинки другого стиля. Правила и порядок добавления объекта — `docs/ART.md`.
- После изменений рендера проверять FPS и время кадра (`renderer.frameMs`), память — `renderer.memoryStats()`.
- `src/render/terrain.ts` (и всё, что он импортирует) выполняется также в Web Worker: без `document`/`window`; холсты — только через `createCanvas`.
- Окружение за картой (`environment.ts`) — только визуальное: не добавлять туда ничего, что выглядит как актив игрока или доступная земля.
